# Proposal

## Why

Живые опыты на стенде (26.11.2026, `docs/DEVICE-FACTS.md`, раздел 9) показали, что датчик отдаёт
новое значение регистра не сразу: первые ~300 мс чтение иногда возвращает **предыдущее** значение,
с 500 мс расхождений нет (2–3 случая из 10 на коротких паузах, 0 из 10 на 500 мс и больше).

Библиотека читает подтверждение сразу после записи. Значит корректная запись иногда выглядит как
`WriteVerificationError` — ошибка в нашу сторону, и пользователь увидит «датчик сохранил другое
значение» там, где всё сохранилось.

Там же уточнились два диапазона из карты регистров, которые оказались неверными:

- дальность обнаружения: значения 40 и 50 отклоняются, а 60…90 устройство молча **зажимает** до
  100. Значит реальный минимум — 1.0 м, а карта говорила «от 60».
- ближняя граница: 0…29 зажимаются до 30, то есть минимум 0.3 м; карта разрешала 0.
- порог освещённости: 4200 принимается, 4201 отклоняется. Карта говорила «до 1000», то есть
  библиотека не давала выставить порог выше 10 лк при разрешении 0.1.

Ещё одно следствие опытов, важное не для библиотеки, а для интеграции: адрес на шине и скорость
обмена применяются **сразу**, без перезапуска питания. Гипотеза о «до перезапуска» не подтвердилась,
и это записано в фактах.

## What Changes

- Подтверждение записи: библиотека ждёт появления нового значения до 1 с, читая повторно, и только
  потом поднимает `WriteVerificationError`. Ожидание — не фиксированная пауза, а опрос: на здоровом
  датчике значение появляется на первом или втором чтении.
- Диапазон дальности в метаданных: 1.0…10.0 м вместо 0.6…10.0.
- Диапазон ближней границы: 0.3…10.0 м вместо 0.0…10.0.
- Диапазон порога освещённости: 0…420.0 лк вместо 0…10.0.
- README библиотеки и факты получают правило суммы `shielding + entry_indent < detection`, которое
  датчик проверяет сам и сообщает исключением `0x02`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `mtdx62-registers`: подтверждение записи учитывает задержку устройства; два диапазона исправлены.

## Impact

- Версия библиотеки 0.4.2: исправление, API не меняется.
- Интеграция не меняется, но её будущее изменение про редактирование настроек теперь знает, что
  адрес и скорость нельзя менять, не переподключая запись: связь рвётся сразу.
