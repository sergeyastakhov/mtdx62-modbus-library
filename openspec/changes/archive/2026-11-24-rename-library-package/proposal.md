# Proposal

## Why

Модуль библиотеки назывался `mtdx62` — так же, как домен интеграции и каталог
`custom_components/mtdx62`. Пока оба лежат рядом, это ломает импорт: запуск из каталога с
компонентом подхватывает его вместо библиотеки, а `mypy` считает `mtdx62.const` файлом
интеграции. Коллизия уже потребовала обходной настройки в интеграции и всё равно оставляет
ловушку для следующего, кто запустит код из неудачного каталога.

Сквозное правило зафиксировано в `conventions/module-naming`. Это изменение приводит библиотеку
к нему.

## What Changes

- Дистрибутив переименовывается из `mtdx62` в `mtdx62-modbus-library`, импортируемый модуль — в
  `mtdx62_modbus_library`.
- Каталог пакета в `src/` переименовывается вместе с модулем, каталог библиотеки в рабочем
  пространстве — в `libraries/mtdx62-modbus-library`.
- **BREAKING**: потребитель обязан поменять импорт и имя зависимости. Версия поднимается до
  `0.3.0`.
- Поведение не меняется: регистры, разбор значений и публичный API остаются прежними.

## Capabilities

### New Capabilities

Нет: поведение библиотеки не меняется.

### Modified Capabilities

- `mtdx62-registers`: добавляется требование к имени пакета и модуля — это часть контракта, потому
  что по этому имени потребитель подключает библиотеку.

## Impact

- `mtdx62-modbus-library` 0.3.0 на PyPI; прежний дистрибутив `mtdx62` снимается, чтобы не
  оставлять две версии одного кода.
- Интеграция `mtdx62`: импорты, `requirements` в манифесте, `loggers`, `mypy_path`, тестовые
  зависимости.
- Спецификация и документация библиотеки, а также ссылки в рабочем пространстве.
