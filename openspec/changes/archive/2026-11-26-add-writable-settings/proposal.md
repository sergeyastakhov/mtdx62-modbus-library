# Proposal

## Why

Сейчас библиотека умеет только читать. Параметры датчика — дальность, ближнюю границу, задержки,
чувствительность, отступ зоны входа — пользователь задаёт ИК-пультом, а интеграция их лишь
показывает. Пульт ничего не отображает и не подтверждает: нажал кнопку — и что записалось, видно
только по поведению датчика.

Библиотека при этом общего назначения. Её будут использовать не только интеграции, построенные на
опросе: скрипт для настройки партии датчиков на столе, мастер миграции адресов на шине,
диагностическая утилита. Всем им нужен полный доступ к регистрам, а не тот урезанный набор,
который безопасен в одном конкретном режиме работы. Поэтому библиотека даёт инструмент записи, а
решения о том, что и когда писать, остаются вызывающей стороне.

Отсюда три следствия, которые и определяют это изменение:

1. Записываемыми становятся все параметры, включая адрес на шине, скорость, чётность и активный
   отчёт. Ограничения на них — дело интеграции, которая строится на опросе и знает свои риски.
2. Библиотека не проверяет состояние устройства перед записью. Это политика уровня интеграции:
   скрипт, меняющий десять настроек подряд, не должен получать десять лишних чтений кода
   состояния, тем более что пакетной записи здесь нет.
3. Библиотека подтверждает запись чтением. Это не политика, а свойство протокола: ответ «записал»
   означает лишь, что кадр принят, и без чтения нельзя отличить сохранённое значение от зажатого.

Вторая причина прежняя: граница ответственности. Интеграция не должна знать ни адресов регистров,
ни допустимых значений — иначе при следующем датчике того же семейства их придётся дублировать.
Библиотека отдаёт метаданные параметра, интеграция строит по ним сущности.

## What Changes

- Появляется публичный список записываемых параметров с метаданными: имя, минимум, максимум, шаг,
  единица, сырые границы.
- Появляется запись одного параметра: проверка диапазона до обращения к шине, запись, чтение блока,
  сравнение и обновление кеша.
- Записываемыми становятся тринадцать параметров: `0x0000…0x000C`. Регистр `0x000D` остаётся
  только для чтения: его смысл неизвестен.
- Библиотека MUST NOT читать код состояния в рамках записи и MUST NOT отказывать в записи по
  состоянию устройства. Рекомендация «проверьте код состояния, если пишете в неисправный датчик» —
  в документации, не в коде.
- Появляется собственная ошибка `WriteVerificationError` (расхождение при подтверждении) от общего
  `Mtdx62Error`. Ошибки обмена по-прежнему пробрасываются из `modbus-connection` без подмены.
- Версия библиотеки — 0.4.0: добавление, обратной совместимости не ломает.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `mtdx62-registers`: требование «Библиотека только читает устройство» заменяется набором
  требований о записи.

## Impact

- Код библиотеки и её тесты; документация: README получает раздел о записи и о рисках, которые
  библиотека оставляет вызывающей стороне.
- Интеграция получит запись отдельным изменением (`add-settings-editing` в её корне) и там же —
  ограничения: не писать `unit_id`, `baudrate`, `parity` и `active_report`, либо писать их только
  через сценарий с согласованным переподключением. Эти ограничения в библиотеке не живут.
- Живой опыт нужен только для проверки гипотез (поведение связи после смены адреса или скорости,
  смысл `0x000B`/`0x000C`), но он больше не блокирует API: библиотека сможет записать эти
  параметры и до опыта.
