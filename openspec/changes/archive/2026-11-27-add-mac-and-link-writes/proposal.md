# Proposal

## Why

Две связанные проблемы выяснились, когда интеграция начала писать в датчик.

**Параметры связи нельзя подтверждать чтением.** Библиотека подтверждает каждую запись повторным
чтением — это правильно для обычных параметров, но для адреса, скорости и чётности проверка
обречена: датчик применяет значение сразу и начинает отвечать по новым параметрам, а старое
соединение молчит. Получается ложная ошибка на успешной записи. Интеграция обходила это прямым
вызовом `settings.write`, то есть знала о внутреннем устройстве библиотеки больше, чем должна.

**Три параметра логично менять вместе.** Смена адреса без скорости и чётности почти никогда не
нужна: датчик переезжает на другую шину целиком. Регистры `0x0007…0x0009` идут подряд, значит
одна функция `0x10` записывает все три за одно обращение — это меньше кадров и меньше шансов
оставить датчик в промежуточном состоянии между двумя отдельными записями.

Заодно выяснилось, что регистр `0x000D`, который в карте назван «код MAC», до сих пор не
читается вообще. Значение нужно для диагностики: по нему видно, тот ли это экземпляр, и оно
полезно в отчёте о проблеме. Писать в него по-прежнему нельзя: смысл регистра до конца не
понятен, а `1` на единственный регистр MAC-адреса не похожа.

## What Changes

- `settings.mac_code` читается из `0x000D` и доступен только для чтения.
- `async_write` для адреса, скорости и чётности больше не читает подтверждение: запись идёт, кеш
  не обновляется, потому что читать уже нечего.
- Новый метод `async_write_link_settings(unit_id=…, baudrate=…, parity=…)` пишет три регистра
  одним запросом `0x10`, проверяя каждое значение до обращения к шине.
- Версия библиотеки 0.5.0: добавление, обратной совместимости не ломает.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `mtdx62-registers`: чтение кода MAC, запись параметров связи без подтверждения, пакетная запись
  трёх параметров.

## Impact

- Интеграция получает то, что ей нужно: сенсор кода MAC для диагностики и запись параметров шины
  без обходных путей.
- Отдельно проверяется на живом устройстве: принимает ли датчик одну запись трёх регистров
  `0x0007…0x0009`. По стандарту это обычная FC16, но проверка нужна до выпуска.
